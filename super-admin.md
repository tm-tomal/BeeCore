# IMPLEMENTATION GAP AUDIT

Audit date: 2026-08-19 (revised)

Status definitions:
- IMPLEMENTED: A usable Super Admin flow exists and is access-controlled.
- PARTIAL: Some data or UI exists, but the complete lifecycle or safeguards are missing.
- NOT STARTED: No dedicated Super Admin domain model, workflow, or screen exists.

Important scope distinction:
- The current Packages, Customer Subscriptions, Invoices, Payments, and Reports modules operate inside an ISP tenant workspace.
- They are not BeeCore SaaS plans, tenant subscriptions, SaaS invoices, SaaS payments, or platform analytics.
- Those platform-level domains need separate models, ledgers, lifecycle rules, and Super Admin screens.

## CURRENTLY USABLE SUPER ADMIN CONTROLS

- Platform dashboard with tenant, user, customer, subscription MRR/ARR, expiry, and audit summaries.
- Tenant create, detail, edit, active/suspended status, non-destructive archive, subscription assignment, and audited impersonation.
- SaaS plan creation/edit/archive with pricing, trial, grace, and core tenant limits.
- Tenant subscription plan/cycle/status assignment with period dates, price snapshots, auto-renew setting, and history.
- Platform and tenant user creation/edit/activation/deactivation with fixed role and tenant assignment.
- Self-delete, self-demotion, and self-deactivation protection for the signed-in Super Admin.
- Scheduled subscription automation: trial conversion, renewal, non-renewal expiry, overdue marking, and grace-based suspension.
- SaaS invoice ledger generated automatically from subscriptions, with manual payment recording and automatic tenant/subscription reactivation once fully paid.
- Plan usage vs. customer/staff/reseller limits shown on the tenant detail page.
- Cross-tenant audit activity list with action and tenant filters.
- Role-protected routes and Livewire actions.

## CRITICAL RISKS IN THE CURRENT SUBSET

1. Archived tenants do not yet have a restore workflow or archive dependency report.
2. Subscription renewal/expiry/suspension automation has no customer-facing or Super Admin notifications yet.
3. There is no usage-metering ledger for SMS, email, API, or storage, so only customer/staff/reseller counts can be checked against plan limits.
4. SaaS payments are manual only; there is no gateway integration, verification, or refund workflow.
5. Editable secrets and provider credentials do not yet have encrypted storage or rotation workflows.
6. Queue, scheduler, backup, and infrastructure health are not visible to operators.
7. Fixed roles cannot express the granular platform permissions required by this document.

## RECOMMENDED DELIVERY ORDER

### P0 - SaaS Commercial Core

1. Complete tenant archive recovery and pending/approval lifecycle.
2. Add renewal/expiry/suspension notifications (email/in-app) alongside the existing scheduled automation.
3. Add SaaS invoice credits, refunds, adjustments, and dedicated financial reports.
4. Implement usage metering and limit enforcement for storage, API, SMS, and email (customer/staff/reseller limits are already visible).
5. Add plan feature entitlements, per-tenant overrides, and upgrade/downgrade rules.

### P1 - Operations and Security

1. Add configurable role/permission management and account activation/suspension.
2. Add password reset, forced reset, 2FA, session/device history, force logout, lockout, and failed-login auditing.
3. Add system settings with encrypted secrets and audited changes.
4. Add queue/failed-job, scheduler, database, storage, and service health monitoring.
5. Add backup status, retention, restore workflow, and tenant data export/archive.

### P2 - Integrations and Communication

1. Add payment gateway registry, adapters, webhooks, monitoring, and reconciliation.
2. Add SMS/email provider management, quotas, pricing, templates, delivery logs, and usage billing.
3. Add network integration registry, encrypted credentials, health checks, and request/failure logs.
4. Add notification templates, announcements, and support ticket management.

### P3 - Expansion

1. Add platform analytics, exports, churn/conversion metrics, and historical trends.
2. Add localization, multi-currency formatting, white label, and custom domains.
3. Add API management, customer app controls, media services, and advanced add-ons only after the commercial and operational foundations are stable.

## NEXT IMPLEMENTATION SLICE

The lifecycle, SaaS plan, subscription, tenant detail, subscription automation, and SaaS invoice/payment ledger foundation is now implemented and tested (idempotent renewal/expiry/suspension, manual payment settlement with auto-reactivation). The next safe slice should be:

1. Add renewal/expiry/suspension notifications (email and in-app) triggered by the existing automation events.
2. Enforce plan limits at the point of action (e.g., block new tenant staff or customers beyond the plan limit) instead of display-only warnings.
3. Add storage/API/SMS/email usage counters once those subsystems exist.

This keeps the commercial core trustworthy before layering payment gateways, notifications, and broader platform analytics.
